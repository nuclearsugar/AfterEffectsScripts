# JSX Script Blueprint for GenAI

There are a few important pitfalls that genAI tools often run into when creating JSX scripts for After Effects. So this text prompt provides guardrails and best practices to improve it's reliability.

Copy-and-paste the following text prompt into your genAI tool to get jumpstarted.

<hr style="border: none; border-top: 1px solid #d0d7de;">

```
I need you to create a JSX script for Adobe After Effects.

Phase 1: Requirement Gathering
Before writing any code, ask the user to define the task which needs automating. The initial question to the user should be "What would you like the JSX script to automate within After Effects?". After the user responds then you can follow up with clarifying questions until the requirements are unambiguous. Do not proceed to code until the user confirms that you have enough information. At the end of Phase 1, if applicable to the task, ask the user if the operation should be executed for the selected comps in the Project window.

Phase 2: Technical Requirements
When writing the JSX script, adhere strictly to the following:

1. COMPATIBILITY: Use only Adobe After Effects ExtendScript (ECMAScript 3). Absolutely no ES6+ (no let, const, arrow functions, template literals, etc.).
2. SCOPING: Wrap all logic in an anonymous self-executing function. It is important to avoid the common mistake which causes the following error in After Effects scripts: "Illegal 'return' outside of a function body".
3. STRUCTURE: Wrap operations in `app.beginUndoGroup()` and `app.endUndoGroup()`. Use a `try...catch...finally` block; ensure `app.endUndoGroup()` is called within `finally` to prevent undo stack corruption on error.
4. VALIDATION: Check for selection validity (e.g., is a comp selected?). If invalid, use `alert()` to provide a clear, user-friendly error message.
5. PERFORMANCE: For nested loops (e.g., iterating through layers and properties), use `for` loops rather than high-level array methods. Always verify if objects exist (`if (obj !== null)`) before accessing properties.
6. FEEDBACK: Include an `alert()` at the end of the operation. Possible information to include: input parameters, number of compositions processed, number of items affected, any skipped items, or such.
7. NON-DESTRUCTIVE: Do not delete, rename, or modify project items unless explicitly requested.
8. HEADER: Include this comment header:
   // <ScriptName>.jsx
   // Code generated by <Model Name>
   // Date: <Date>
   // Description: <One-sentence summary>
9. OUTPUT: Always provide the complete, runnable JSX script. Never use partial code snippets or placeholders.
```
